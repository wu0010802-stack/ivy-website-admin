# 常春藤的一天背景影片：繪本淡彩動畫六幕（2026-11-11）

使用者看過 11-10 的園方實拍剪輯版（`../day-film-daily-20261110/`，沒有上線）後：「這些影片畫質太差」，接著要求「常春藤的一天用全動畫，不計時間與成本」。這版把背景整支換成手繪感的繪本動畫，六幕對應六張拍立得的時刻。

**這推翻了 11-10 寫下的「背景影片不用 AI 生成孩子」**：那是我依 `PRODUCT.md`「沒有資料不虛構」做的判斷，使用者之後明確要全動畫，以較新的裁定為準。配套做法是讓它一眼看得出是插畫、不是實景：畫風是鉛筆線＋淡彩，角色是畫出來的人物（沒有拿任何真實孩子的臉當參考），左下角圖說寫「繪本動畫 · 情境示意」。真實照片仍在六張拍立得上。

## 風格為什麼是這個

- **接站上既有的語彙**：首頁五校是鉛筆線稿＋淡彩速寫、特色教學頁是水彩。背景用同一種畫法，整頁才是一個世界。
- **不踩「過度卡通化」**（`PRODUCT.md` 反參考）：孩子是自然比例、小點眼睛，不是大頭 Q 版；色調是常春藤的墨綠、葉綠、米白、磚橘、金黃。
- **校舍是義華校**：參考站上的義華線稿，城堡塔樓、橘色磚帶、溜滑梯都對得上。制服與書包照實物配色（白上衣、藍綠下半、斜紅帶；紅藍黃書包），書包上不寫字。
- **第一幕與第六幕同一個機位**：清晨走進校門、黃昏牽著爸爸走出來。影片循環時，黃昏暈回清晨，像日子又過了一天。

## 製作流程

1. **關鍵畫面**：GPT Image 2.6（2688×1520）。先畫第一幕定風格，其餘五幕拿第一幕成品當參考圖，角色與畫風才一致。提示詞在 `prompts.md`。
2. **動起來**：Kling 3.0 pro 圖生影片，每幕 5 秒、24fps、1912×1080、無聲。只要求小而自然的動作（走路、倒水、舀飯、翻頁、吹泡泡、樹葉與光斑）。
3. **放大**：ByteDance 影片放大到 2546×1440（aigc 預設）。鉛筆線與髮絲明顯變銳利，畫風與顏色不變。
4. **剪接**（`build.py`）：
   - 生成檔沒有色彩標記，逐格比對關鍵畫面後以 **BT.601 limited** 解碼（709 會偏藍 4/255）。
   - 幕與幕之間 0.75 秒**水彩暈染**轉場：低頻雜訊＋由左往右的漸層當遮罩，濕邊不規則地掃過去，前緣略深像顏料堆在水邊。濕邊寬度 0.38；0.55 時兩幕的臉會疊影。
   - 亮部軟收（0.60 以上收向 0.90），大標底下沒有接近紙白的像素。
   - 第六幕 4 秒後爸爸走到鏡頭前、頭頂貼到畫面上緣，只用前 4 秒。
5. **手機另有一支直式檔**：直拿手機把橫式硬裁中間，只剩畫面的四分之一寬、還放大三倍。這版從 2560×1440 母帶另出 960×1440，每一幕有自己的鏡頭路徑（`SCENES` 的 `pan`），緩緩從一個人移到另一個人，例如第四幕從趴著看書的 Mei 移到靠著老師睡著的 Hao。一般手機實際看到的是直式檔中間 665px，等於橫式畫面寬度的 26%，鏡頭中心就是照這個窗排的。

花費：Higgsfield 共 80.4 點（關鍵畫面 7 張 7 點、動畫 7 支 61 點、放大 6 支 12 點；帳號從 89.9 用到剩 9.6）。第五幕重做過一次，原因在 `prompts.md`。

## 交付檔

| 檔案 | 規格 | 大小 | 用在 |
|---|---|---|---|
| `day-desktop.mp4` | 1920×1080、24fps、24.7 秒、x264 CRF 24 | 11,915,483 | 桌機；也是 `web/media-src/day-film.mp4` |
| `day-mobile.mp4` | 1280×720、CRF 26 | 4,431,910 | 橫拿手機 |
| `day-portrait.mp4` | 960×1440、CRF 26 | 6,396,737 | 760px 以下（直拿手機） |

紙紋與筆觸每格都在動，位元率比實拍片高：桌機 CRF 21 要 19.5 MB，CRF 24 是 11.9 MB，1:1 細部看不出差別；只做時間軸降噪省不到一成，不用。縮小用 bicubic（lanczos 在鉛筆線旁有振鈴亮邊），再把亮度鎖在亮部上限。

封面 `web/public/assets/day-poster.webp` 是橫式母帶第 0 格（1440×810）。

## 網站端改了什麼

- `video-manifest.json` 多一個 `day-portrait` 鍵。`media-policy.ts`：`assets/day-film-mobile.mp4`（760px 以下才用）對到直式檔，橫拿手機照舊拿 `day-mobile`。`optimize-site-videos.py` 認得這一版；母帶換回沒有直式檔的舊版時，`day-portrait` 自動指回橫式手機檔。
- `styles.css`：10-13 為了躲舞台片左上角台標、寬螢幕貼左上的規則拿掉（沒有台標了，一律置中）。760px 以下封面往右對到 61%，跟直式檔第一格同一個位置，影片淡入時人物不會橫移。
- 圖說：內建文字改成「繪本動畫 · 情境示意」（fixture、後台內建文字）。正式站後台存的還是「義華校 · 遊藝表演」，`public-copy.ts` 只在仍用內建影片且圖說一字不差是舊文字時替換，園方改過的照園方的。
- 後端 `site_import.py`：匯入內建素材時，手機版位拿直式檔。

## 驗證

- **白字對比**（開場那一屏；`measure/rects.cjs` 量文字位置，`measure/contrast.py` 抽格、疊兩層墨綠紗、每段字取最亮像素，不計文字陰影）。舊片是正式站現行的舞台表演片，同一支腳本：

  | 寬度 | 大標「常春藤」／「的一天」 舊 → 新 | 左下圖說 舊 → 新 | 英文小字（金）舊 → 新 |
  |---|---|---|---|
  | 1440 | 2.31／2.37 → 2.62／2.62 | 5.00 → 6.03 | 1.86 → 2.16 |
  | 1280 | 2.33／2.38 → 2.69／2.66 | 5.01 → 5.97 | 1.87 → 2.17 |
  | 1024 | 2.34／2.39 → 2.67／2.69 | 5.06 → 5.97 | 1.86 → 2.15 |
  | 390（直式檔） | 2.30／2.40 → 2.94／2.89 | 4.98 → 6.11 | 1.46 → 1.86 |

  每一項都高於現行版。**量法改過**：縮放改用雙線性（瀏覽器的做法）。11-10 的腳本用 LANCZOS，在鉛筆線旁會多出振鈴亮邊，淡彩插畫的「最亮像素」被量高到差 0.3；實拍片幾乎沒差，所以 11-10 的數字（舊片 2.28）跟這裡的 2.30 差不多。
- **壓縮品質**（對母帶，逐格對齊）：桌機 SSIM 0.978、橫式手機 0.968、直式 0.973。
- **實際播放**（fixture dev server、`measure/verify.cjs`、Chromium）：1440×900 載入桌機檔、390×844 載入直式檔、844×390 載入橫式手機檔，都淡入、在播、沒有 console 錯誤。
- **逐幕看過**：每秒抽格＋細部裁切，臉、手、制服沒有變形；loop 接縫的頭尾兩格並排看是連續的。
- web `typecheck`；web 單元 133 檔 1790 項；admin `vue-tsc`、單元 173 檔 3347 過、1 略過；後端 `test_media_slots.py` 21 項（本機臨時 PostgreSQL）。

## 沒驗證、要知道的事

- Safari／WebKit、iOS／Android 實機沒驗（這台只有 Chromium）。
- **放大後的六支片源不在 repo**（共 57 MB）：留在 Higgsfield 帳號裡，工作編號與雜湊在 `sources.json`。AI 服務不保證重現，要重剪得從那裡下載同一批檔案。
- 拍立得的時段光（`day-film-light`）還是跟著讀者停的那張卡走，跟背景播到哪一幕無關，兩者不同步。要做到「讀到哪張卡、背景就演那一幕」得把六幕拆成各自可循環的片段，另開一輪。
- 圖說寫不寫「AI 生成」由園方決定；現在寫的是「繪本動畫 · 情境示意」，`site-fixture.json` 的 `sourceNote`（官網不顯示）有記是 AI 生成。

## 重製

```bash
python3 -I design/day-film-animation-20261111/build.py --clips <放 s1.mp4 … s6.mp4（放大檔）的資料夾>
cp design/day-film-animation-20261111/day-desktop.mp4 web/media-src/day-film.mp4
python3 -I scripts/optimize-site-videos.py
python3 -I scripts/optimize-site-images.py --only day-poster
```

`--reuse-master` 只重出封面與交付檔。換回 11-10 的實拍版：把 `../day-film-daily-20261110/day-desktop.mp4` 複製成母帶後跑同兩支腳本，並把圖說改回去。
