# 孩子的一天背景影片：園方校園日常片 13 鏡（2026-11-10）

使用者要求重做首頁「常春藤的一天」的背景影片，「不計時間與成本、用一切可用的技術」。正式站原本的背景是義華遊藝表演紀錄（舞台燈光、`2026` 氣球字、台下觀眾），跟六張拍立得「入園→探索→用餐→安靜→午後→回家」的日常時序不搭，10-13 審查就提過「背景改日常片」、當時缺素材。

**不用 AI 生成孩子。** `PRODUCT.md`「真實校園影像優先，沒有資料不虛構」、品牌規範「不把其他學校的素材當常春藤的」——合成的幼兒園小孩兩條都踩；家長一眼看出是假的，招生官網信用就沒了。AI 只用在一件事：把 720 寬的新片放大（見下），畫面內容一格都沒生成。

## 剪輯：依一天的時序，13 鏡、約 23 秒、全部溶接、loop 無縫

入園（三個孩子跑來 → 制服女孩在操場跑）→ 探索（看葉子 → 倒水 → 玩具魚 → 水桌）→ 用餐（女孩拿湯匙，「我自己來」）→ 安靜（小提琴課全景 → 女孩拉琴 → 老師與孩子額頭相碰）→ 午後（紙雪花 → 男孩領跑）→ 回家（全班朝鏡頭跑來）→ 溶回開場。

- **輸出 1440×810、30fps**，與 09-24 定案的背景尺寸相同；明華 4K 是縮小、廣告 1080 放大 1.33 倍、115 由放大檔裁出來剛好是原尺寸。
- **快動作半速**（跑、拿湯匙、拉琴特寫）：`minterpolate` 補到 30fps，同 09-23 首屏做法。預設的動態搜尋在朝鏡頭跑的臉上每隔一格就糊成一片（第一鏡中間的女孩，正好是封面那一格），改 `me=umh:search_param=64` 就乾淨；`blend` 模式是雙影不能用。比較圖：`measure/` 下 `interp-*.png`（工作區）。
- **溶接 0.5 秒**：背景在字底下，硬切比首屏那種節奏搶眼；溶接讓「一天」像時間在走。loop 的接法：第一鏡在序列尾再放一次、同樣溶接，成片從第一鏡溶接完成處起、到最後溶回第一鏡完成處止，`loop` 回到開頭時影格連續、不跳。收尾全班朝鏡頭跑 → 開場三個孩子朝鏡頭跑，接縫像換了一天。
- 2 鏡 115 新片 44.2 秒前還有淡出中的字幕、46.2 起片尾校徽浮上來，取中間；原本試過用廣告片尾的書包特寫收尾，溶接時書包上的字疊在孩子臉上，拿掉。

## 720 寬的新片用 ByteDance 影片放大到 2K

115 新片只有 720×1280，裁 16:9 只剩 720×405，鋪 1440 要放大兩倍。三段先剪成一支 5.2 秒（`measure/` 不進版控的 `f115-segments.mp4`），用 Higgsfield 的 ByteDance 影片放大（2K、`common`、30fps）得到 1440×2560，再從放大檔裁 1440×810。對照 lanczos 兩倍（`compare.png`，工作區）：髮絲、畫框邊緣乾淨、沒有振鈴，臉沒有被改。花 2.07 點數。

## 色彩：同首屏 10-29 第二版，螢幕樣貌燒進像素再標 sRGB

沒有色彩標記的兩支（明華、廣告），瀏覽器以 BT.601 解再抬亮中間調；把這個樣貌（`design/day-film-color-20261025/screen-17.cube`）燒進像素、標 BT.709 原色／矩陣＋sRGB 轉換函數，首屏與這支就是同一個世界。115 新片標 BT.709，以 BT.709 解再套同一個 LUT（Mac 瀏覽器對 709 轉換函數一樣抬亮）。廣告原片的壓縮方塊照 10-24 去方塊。

各鏡只做小幅對齊（`SHOTS` 的 `adjust`）：拿湯匙那鏡原片偏洋紅，中間調往綠拉一點；紙雪花白牆白紙中位 L* 86，壓一點；統計見 `measure/shots.py`。

## 驗證

- **壓縮品質**（對 10-bit 母帶，兩邊 `setpts=N/30/TB` 逐格對齊；這台 ffmpeg 沒有 libvmaf，改報 SSIM／PSNR）：桌機 SSIM 0.989（Y 0.988）、PSNR 45.5 dB（最低一格 26.8，溶接中）；手機 SSIM 0.984、PSNR 43.3 dB。不對齊的話 mkv 時間戳每三格錯一格，會量到 PSNR 31、SSIM 0.95，不是真的。
- **白字對比**（`measure/rects.cjs` 量開場那一屏的文字位置，`measure/contrast.py` 抽格、疊 `styles.css` 兩層墨綠紗、每段字取最亮像素；不計文字陰影與眉標暗暈，新舊同一支腳本、同一組位置）：

  | 1440 | 2.43／2.28 → 2.24／2.26 | 5.08 → 6.00 | 1.79 → 1.92 |
  | 1280 | 2.45／2.29 → 2.25／2.26 | 5.04 → 5.82 | 1.79 → 1.92 |

  大標 171px 高、有 40px 的陰影，這個量法本來就保守（舊片也只有 2.3）；新片最低 2.21、手機反而高一截。全片亮部軟收（`HIGHLIGHT_ROLLOFF`）就是為此：只收開場兩鏡時，水桌、小提琴教室、全班跑那幾鏡大標仍 2.02–2.06（逐格資料在工作區）。圖說每個寬度都比舊片高。
- **實際播放**（fixture dev server、`measure/verify.cjs`）：Chrome 1440 載入 `day-desktop-528a64153de0.mp4`、Chrome 390 手機模擬載入 `day-mobile-6257f0430b3e.mp4`，都淡入（`.is-ready`）、在播、沒有 console 錯誤；截圖 `verify-chrome-*.png`（工作區）。WebKit 這台沒裝，沒驗。

## 重製

```bash
python3 -I design/day-film-daily-20261110/build.py \
  --minghua <明華寶貝的快樂城堡.mp4> --ad <常春藤廣告+配音.mp4> --f115 <115影片.MP4> \
  --f115-upscaled <放大後的三段合併檔>
cp design/day-film-daily-20261110/day-desktop.mp4 web/media-src/day-film.mp4
python3 -I scripts/optimize-site-videos.py
python3 -I scripts/optimize-site-images.py --only day-poster
```

三支原片都核對雜湊（`build.py` 的 `SOURCES`）；放大檔的雜湊記在 `manifest.json`，重做放大結果不會一樣（AI 服務不保證重現），沒有放大檔時拿掉 `--f115-upscaled` 會以 lanczos 兩倍代替。中間檔在 `output/day-film-daily-20261110/`（不進版控）。
