## 剪輯（`build.py` 的 `SHOTS`）

老師擁抱 → 盪架上的男孩 → 制服女孩大笑 → 圍著樂器大笑 → 舉手 → 圍看色盤 → 跪坐聽講 → 大笑 → 老師抱孩子 → 紫色手掌 → 抬頭大笑 → 踢足球 → 抱籃球。11.73 秒、352 格（第二版 9.2 秒）。

- 裁 1080:800 的框（與首屏同比例），預設 2160×1600 放在 y=461：上緣避開校徽、下緣停在字幕上方約 50px，**不補洞**。抬頭大笑要往上移（y=400），寬度縮到 1740、靠左躲校徽。
- **開場＝封面**：老師擁抱從 3.02 秒開始。更早的格大半是老師的後腦，封面與分享圖看不到孩子的臉。
- **跪坐聽講往下放大**（x=190、y=700、寬 1780）：y=461 時上緣一排窗戶正好在導覽列後面，導覽白字對比只剩 4.54。
- 舉手只取到 13.90 秒（之後有手揮過鏡頭）；老師抱孩子從 6.20 秒起（之前左側模糊手臂比較大）；抱籃球取到 40.70 秒（之後籃球被裁到）。
- 沒用的鏡頭：外師特寫（主角是大人）、戴口罩的孩子、低頭看不到臉、純手部特寫。

## 色彩：照原片，不調色

原片沒有色彩標記，Mac 的 Chrome／Safari 以 BT.601 解再抬亮中間調。把這個「螢幕上的樣子」燒進像素（`design/day-film-color-20261025/screen-17.cube`，10-25 孩子的一天實測的 LUT），交付檔再標 BT.709 原色／矩陣＋sRGB 轉換函數，看起來就跟打開原片一樣。中間檔保留原片 YUV 值、不轉矩陣，後段跟瀏覽器一樣以 BT.601 解；明華 4K 縮下來沒有壓縮方塊，不去方塊。

**螢幕實測**：Chrome 原尺寸播放、同一格停格截圖，對沒有標記的原片（同裁切，`setpts=N/30/TB` 讓時間戳規則；concat 接起來的片時間戳有空隙，越後面越對不準）13 格：H.264 平均差 1.44/255（偏移 +0.01），AV1 2.01（偏移 −1.23）。比對影片要用支援 Range 的伺服器播，Python `http.server` 不能跳格。

**地雷**：各鏡中間檔格式要一致才能用 concat 複製串流接起來；第二版舊鏡頭串兩個 `lut3d` 時被協商成 `yuva420p10le`，接起來後段解碼報 `quant_table_index out of range`，所以中間檔輸出固定 `-pix_fmt yuv420p10le`。

## 封面與分享圖

`hero-campus-restored-v1-still.webp` 是中間檔第 0 格（`build.py` 的 `poster`），換片後跑 `optimize-site-images.py --only hero-campus-restored-v1-still` 重產衍生圖與分享圖，再手動刪掉沒被 `image-manifest.json` 引用的舊衍生圖。封面接影片第一格平均差 2.55/255。

分享圖（1200×630）全站固定以垂直 40% 為中心裁，這張的孩子臉在下半，會切到嘴；`optimize-site-images.py` 加了 `OG_CENTERING`，只有首屏這張用 75%。

替代文字（`site-fixture.json` 的 `heroImageAlt`，後台沒設首屏封面時用它）改成「常春藤的老師抱住孩子們、大家笑成一團的校園影片畫面」；`web/tests/fixtures/overlay-baseline-20260925.json` 同步。

## 重製

```bash
python3 -I design/hero-mix-minghua-20261029/build.py <明華寶貝的快樂城堡.mp4>
cp design/hero-mix-minghua-20261029/hero-desktop-h264.mp4 web/media-src/hero-campus.mp4
python3 -I scripts/optimize-site-videos.py
python3 -I scripts/optimize-site-images.py --only hero-campus-restored-v1-still
```

原片雜湊寫死在 `build.py` 的 `SOURCE_SHA256`。中間檔放在 `output/hero-minghua-more/`（不進版控）。第二版的 `match.py`（舊鏡頭對齊明華）在 `602a2b0d`。
