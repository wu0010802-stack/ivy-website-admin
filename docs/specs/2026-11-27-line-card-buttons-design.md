## 1. 原則（沿用前幾輪）

- 群組只放數字、校名、日期、家長稱呼；不放電話、Email、孩子資料（10-05 裁定）。
- 唯讀的按鈕同指令：2026-09-29 以前綁定、沒貼過驗證碼的舊群組也能用；會寫入的按鈕只認驗證過的群組。
- 回覆一律 reply（不計則數）；postback data 只放動作代碼、代號、日期，不放中文。
- 一則推播帶多個訊息物件，LINE 照收件人數算一則（同 @所有人 跟在卡片後面的做法），所以週報多一張選校卡不加則數。

## 2. 報表的各校明細（項目 10）

**原本的提案是「按義華＝幫你打『義華 上週統計』」，施工時發現那一列週報裡已經有了，按了只會看到同一行字。**
改成真正的「明細」：週報、月報只有每校一行總數，明細補上總數看不出來的東西。

- **入口**
  - 月報卡片：footer 加五校按鈕（三顆一列）。
  - 週報：純文字（4800 字上限），後面同一次推播多一張「看各校明細」小卡，放五校按鈕。「週報」指令的回覆也一樣。
  - 只放營運中的校區，順序固定（義華、明華、崇德、國際、仁武）；按鈕字用短名（去掉「校」）。
- **postback**：`ivy:rpt:<w|m>:<校區 key>:<那一期第一天 YYYYMMDD>`。帶日期的理由：下週再按舊週報的按鈕，看到的還是那一週，不會變成「現在的上週」。
  - 驗證：週報的第一天要是週一、月報要是 1 號、不能晚於今天、校區要在營運中名單裡；不符就不回應（不是我們編的）。
  - 授權：總部群組才回（非總部群組回「這個指令只有總部群組可以用。」）；唯讀，不要求驗證碼。
  - displayText「義華明細」：群組看得出是誰按的；這句不能是群組指令（測試會檢查）。
- **明細卡內容**（同一期、同口徑：依預約送出日、排除測試／重複）
  - 預約筆數、進件管道（官網表單／電話／LINE／親自到園／外部預約網站，0 不列）。
  - 官網來源：官網預約的**第一次進站**來源（字面同後台 `TOUCH_SOURCE_LABELS`；沒記到的寫「沒記到」）。
  - 結果：到場、未到場、待標記、尚未參觀、取消，加到場率；取消再分家長取消／園方取消／占位逾期。
  - 預繳筆數（同週報的 `deposited_cases`）。
  - 名單：未到場、待標記各列家長稱呼與參觀日，各最多 8 位，超過寫「等 N 位」。這兩種是總部看完數字最常要追的。
  - 按鈕：「開成效統計」（有設 admin_origin 才放，帶 `openExternalBrowser=1`）。
  - altText：「義華校 11/16–11/22 明細」（不放稱呼）。

## 3. 查詢結果的切換鈕（項目 11）

- **做法**：LINE 快速回覆（quick reply）。可以掛在任何訊息上（文字與卡片都行），出現在輸入框上方，按了以按的人的名義送出那句指令，再照一般指令處理（同 @選單 的按鈕）。
  - 不用卡片 footer 的理由：名額、休假日、待辦、統計是純文字，掛不了按鈕；另外多推一張卡會讓群組很吵。
  - 限制（LINE 文件）：只在 iOS／Android 顯示（電腦版不顯示，但指令照樣能打）；群組有人再傳訊息就收起來。所以只當「看完順手切」用，不取代選單。
  - 最多 13 顆、字面 20 字內；這裡每則 2–4 顆。
- **掛在哪**：群組指令的查詢結果（含「沒有資料」那種回覆）。選單、說明、權限不足（總部專用、這個群組查不到某校）、額度不掛。推播（每日摘要、週報、月報、案件卡）不掛。
- **切到哪**（同一類的其他期間＋相關的一兩個）：

| 這次查的 | 切換鈕 |
|---|---|
| 今天參觀 | 明天參觀、本週參觀、待標記、今天名額 |
| 明天參觀 | 今天參觀、本週參觀、下週參觀、明天名額 |
| 本週參觀 | 今天參觀、明天參觀、下週參觀、本週名額 |
| 下週參觀 | 本週參觀、下週名額 |
| 11/28 參觀 | 前一天（過去的不放）、後一天、11/28 名額 |
| 待標記 | 今天參觀、待追蹤、待辦 |
| 待追蹤 | 待標記、待辦 |
| 今天／明天／本週／下週名額、名額（近 7 天） | 同類其他期間（2 顆）＋同期間的參觀 |
| 11/28 名額 | 前一天（過去的不放）、後一天、11/28 參觀 |
| 休假日 | 本週名額、待辦 |
| 待辦 | 待標記、待追蹤（招生入學開著才放）、今天參觀、休假日 |
| 今天聯絡 | 今天參觀、待辦 |
| 本週／上週／本月／上月統計（總部） | 同類其他期間＋週報或月報 |
| 週報／月報（總部） | 月報或週報、本週統計或本月統計 |

- 日期的前後一天：是今天、明天就寫「今天參觀」「明天參觀」，其餘寫「11/29 參觀」。
- 指令前加了校名（「義華 今天參觀」），切換鈕也帶同一個校名（「義華 明天參觀」）；週報、月報、額度與校區無關，不帶。
- 每顆切換鈕的字都要能被指令解析器認出來（測試逐一檢查），避免改了指令字面卻留下按了沒反應的鈕。

## 4. 統計異常卡片（項目 12）

**原本提案寫「知道了，今天不再提醒」，施工時確認提醒本來就一天只推一次，「今天」沒有意義。**
改成：按「知道了」＝**同樣的問題 3 天內早上不再提醒**（問題還在，第 4 天起照常提醒；新的別種問題照推）。
群組裡看得到是誰按的（displayText「知道了，我來看」），其他人知道有人在處理。後台「成效統計」頁頂端照常顯示，不受影響。

- **提醒改成卡片**：標題「官網統計可能有狀況（11/26 週三）」、每項一行、footer 兩顆：
  - 「知道了，先不提醒」（postback `ivy:shm:<檢查的那天 YYYYMMDD>:<問題代碼,…>`）。
  - 「開成效統計」（有設 admin_origin 才放，帶 `openExternalBrowser=1`）。
  - altText 同標題（沒有個資）。
- **按下去**：
  - 只認貼過驗證碼的總部群組（會寫入）；不是總部群組回「這個指令只有總部群組可以用。」
  - 問題代碼只收四種（traffic_zero、engagement_low、attribution_missing、ga4_silent），其他不回應。
  - 卡片太舊（檢查的那天早於 2 天前）回「這則提醒已經過了，請看最新的提醒」，避免拿兩週前的卡片把現在的問題按掉。
  - 寫 `stats_health_mutes`（每種問題一列：暫停到哪天）。暫停到＝今天＋3 天；已經暫停到更晚的不縮短。
  - 回覆：「已記下：GA4 沒收到事件。11/28–11/30 早上不再提醒；12/1 起問題還在會再提醒。後台成效統計頁照常顯示。」
  - 稽核：`line.group.stats_health_mute`，metadata 記問題代碼、暫停到哪天、群組 id、按的人的 userId（後兩者只有 notifications.manage 看得到，同其他群組按鈕）。
- **推播時**：`send_due_alerts` 先拿掉還在暫停中的問題再推；全部都在暫停中就不推、也不記已推。
- **一個群組按了，所有總部群組都暫停**（暫停的是「這個問題」，不是「這個群組」）。

## 5. 不做

- 案件卡、名單、摘要上的其他寫入按鈕（確認預約、園方取消、關場次等，第 1–9 項使用者沒挑）。
- 每日摘要與其他推播掛切換鈕。
- 明細裡的孩子資料、電話、Email、家長自填文字。
- 校區群組的報表明細（週報、月報本來就只給總部）。

## 6. 施工結果（2026-11-27）

- **檔案**：`notifications/line.py`（`with_quick_reply`）、`line_flex.py`（明細鈕、週報選校卡、明細卡、統計異常卡）、`line_group_commands.py`（`switches`，`_respond` 改回傳多則訊息）、`line_group_actions.py`（`rpt`／`shm` 分派；唯讀動作不要求驗證碼）、新 `line_group_report_actions.py`、`line_group_reports.py`（`report_period`、`campus_detail`）、`line_reports.py`（`build` 回傳多則）、`operations/stats_health.py`（卡片、`muted_keys`、`mute`）、`operations/models.py`（`StatsHealthMute`）、`audit_service.py`（新動作進 `LINE_GROUP_ACTIONS`、搜尋鍵加 `issues`、`muted_until`）、migration `d8b3f1a6c240`；admin 的動作／對象／欄位標籤與 LINE 通知頁說明。
- **和設計不同的地方**
  - 週報選校卡的 altText 寫「週報：看各校明細」：它跟在週報後面，聊天列表與通知顯示的是最後一則的 altText。
  - 切換鈕多一道過濾：「月/日」約半年後的日子會被 `_day_of` 認成半年前的同一天，認成過去日期的切換鈕不放（測試抓到的）。
  - 「知道了」寫入用 `INSERT … ON CONFLICT DO UPDATE`（取兩者較晚的日期），兩個人同時按、列還不存在時不會撞主鍵。
  - 說明（「指令」）多一行：手機查詢結果下方會出現切換鈕。
- **驗證**：見 README 2026-11-27 段落的表格。
- **沒驗**：手機 LINE 上的實際樣子（快速回覆、明細卡、統計異常卡）；postback 的 displayText 在真群組會不會另外送出訊息事件（「義華明細」「知道了，我來看」都確認不是指令，送出也不會觸發查詢）。
