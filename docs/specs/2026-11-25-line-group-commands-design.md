# 總部群組的指令擴充（2026-11-25）

使用者在群組試「@當日參觀」「@待標記」沒有回應，看完可加的指令（A–F）後說「以總部群的指令為準，我要擴張這個群組的指令」。
本文以**總部群組（一次看五校）**為基準設計整套指令；校區群組用同一套、只看自己服務的校區，統計與額度只給總部群組。
前一輪：`2026-11-25-line-more-features-design.md`（待標記、指定日期）、`2026-11-17-line-group-interactions-design.md`（指令與按鈕的原則）。

共同原則不變：整則訊息完全相符才算指令；回覆一律 reply（不計則數）；不放電話、Email、孩子資料；每群組每分鐘最多 6 次查詢；
只處理已綁校區或總部的群組。

## 1. 指令怎麼認（A）

- 先把全形轉半形（NFKC：「＠」「／」「１１」），去頭尾空白。
- **手打的 @**：訊息開頭是「@」但沒有真的標記官方帳號（例如「@待標記」）→ 拿掉「@」當成有標記。
  「@某某 待標記」這種手打名字的，再試一次第一個空白後面的字。真的標記照 11-17 的做法（依 mention 的位置切掉）。
- **指定校區**（總部群組用得到）：指令前面可以加校名，「義華 今天參觀」「明華校待標記」。校名取資料庫的校區名稱，有沒有「校」字都認。
  群組沒有服務那一校就回「這個群組查不到○○校。」
- 短字（不加「參觀」）只有標記官方帳號或手打 @ 時才認，避免閒聊誤觸。

| 指令 | 同義字 | 有 @ 時的短字 |
|---|---|---|
| 今天參觀 | 今日參觀、當日參觀 | 今天、今日、當日 |
| 明天參觀 | 明日參觀 | 明天、明日 |
| 本週參觀 | 這週參觀、本周參觀、這周參觀 | 本週、這週、本周、這周 |
| 下週參觀 | 下周參觀 | 下週、下周 |
| 11/28 參觀 | | 11/28 |
| 待標記 | 未標記 | |
| 待追蹤 | | |
| 今天名額、明天名額、本週名額、下週名額、11/28 名額 | 今日名額、明日名額、本周名額、下周名額 | 名額（今天起 7 天） |
| 休假日 | 停課日 | 休假、停課 |
| 待辦 | | |
| 本週統計、上週統計、本月統計、上月統計（總部） | 周的寫法 | |

| 指令 | 指令說明 | 說明、幫助 |

## 2. 待追蹤（B）

- 招生訪視裡「下次聯絡時間已到」的（`admissions/follow_up.condition("due")`，同後台待追蹤的「到期」），依應聯絡時間舊到新。
- 每筆一張卡：校區、家長（聯絡人稱呼，同樣拿掉網址、限 20 字；**不放孩子姓名、電話**）、參觀日、應聯絡時間（逾期寫幾天）。
  按鈕：「明天聯絡／3 天後聯絡／1 週後聯絡」（沿用 11-25 的 `rff`，台北 10:00），有對應預約而且有設後台網址時多「開啟案件」。
- 第一張總覽列各校筆數；超過 11 筆寫「另有 N 筆，請開後台」。沒有就回「目前沒有到期的待追蹤。」
- 招生入學功能關閉時回「招生入學功能沒有開啟，沒有待追蹤名單。」
- `rff` 原本只接受「由官網預約建立」的訪視（結果卡的前提）；名單裡也會有園方自己建的訪視，所以**只有下次聯絡這個動作**放寬成不需要對應預約，
  其餘檢查（群組已驗證、校區授權、未匿名化、未退出、招生入學開著、樂觀鎖）不變。

## 3. 名額（C）

- 單日（今天／明天／指定日期）：每校列每個場次「10:00–11:00　已約 1／2 組」，額滿、已關閉（停止申請或休假）、今天已開始的另外標明。
- 多日（本週＝今天到週日、下週、@名額＝今天起 7 天）：每校每天一列「11/26（三）剩 3 組（2 場）」，沒有場次的日子不列；今天已開始的場次不算。
- 已約數與後台月曆同一個算法（`slot_service.count_booked_by_slot`：已確認、已完成、未到場都占名額）。
- 沒有場次的校區寫「這段期間沒有場次」；不是線上預約模式的校區（電話、LINE、暫停）加註目前的預約方式。過去的日期回「已經過去的日期請到後台查看。」
- 純文字回覆，只有數字。

## 4. 休假日（E）

- 今天起 14 天內的休假日（含停班停課），依日期列：日期、校區、原因（園方填給家長看的那句，拿掉網址、限 30 字）、那天還有幾筆已確認的預約要聯絡
  （同後台「待人工處理」：`slot_service.awaiting_visit_condition`，排除測試／重複）。沒有就回「近 14 天沒有休假日。」

## 5. 待辦

- 每校一列現在的數字：今天參觀（已取消不算，同總覽今日行程）、待標記、待追蹤（招生入學開著才列）、停課要聯絡（`attention.needs_attention_condition`）。
  多校時加合計。條件都和後台總覽同一份。最後一行提示可以用哪個指令看名單。

## 6. 統計（D，只有總部群組）

- 本週（週一到今天）、上週、本月、上月。每校一列＋合計：預約、到場、未到場、取消、待標記、尚未參觀、預繳，以及合計的到場率。
- **口徑同後台成效統計「預約結果」**（`booking_outcomes_service.booking_outcomes`）：期間依預約送出日，排除測試／重複；
  到場率＝到場 ÷（到場＋未到場）。預繳＝這批預約裡招生訪視預繳過的（同一支檔案的 `_deposited`）。標題寫明「依預約送出日」。
- 後台這組數字限總管理者（`admissions.stats`），所以只給總部群組（總部群組由總管理者在後台指定）；其他群組回「這個指令只有總部群組可以用。」

## 7. 額度（F，只有總部群組）

- 每個設好的官方帳號本月已用／上限（`line_accounts.all_statuses`，5 分鐘快取），用到八成加註「快用完了」，查不到寫「查不到（金鑰可能失效）」。

## 8. 選單與說明

- 只 @ 官方帳號：選單改成兩顆一列，今天／明天／本週／下週參觀、待標記、待追蹤、今天名額、休假日、待辦、指令；總部群組多本週統計、額度。
- 「指令」與新成員說明列出這個群組能用的全部指令（總部群組多統計與額度兩行）。

## 9. 不做

- 用姓名或電話找預約、在群組改期或取消、在群組打字填欄位（11-17 的原則）。
- 預約層的「下次聯絡」（參觀前）不列進待追蹤：參觀後的追蹤在招生訪視（10-04 規格）。

## 10. 施工結果（2026-11-25）

- 解析：`line_group_commands._addressed`（剝 @、NFKC）＋ `parse`（完整指令、短字、日期、校名前綴）。手打「@某某 指令」的第二段只認完整指令、
  不認短字（「@小明 今天」不算）；訊息裡有真的標記（標記別的成員）就不當成手打 @。
- 沒對上的訊息只有在「有叫官方帳號」或含指令關鍵字時才查校名再試一次，一般閒聊不多查資料庫。
- 報表查詢集中在 `line_group_reports.py`；名額、休假日、待辦、統計、額度是純文字（超過 4,800 字截斷並提示加校名），待追蹤是卡片。
- `line_group_actions._field_visit` 多 `require_booking`：只有 `rff`（下次聯絡）傳 False。
- 統計的預繳數：`booking_outcomes_service.deposited_cases`（新的公開函式，沿用同檔的 `_deposited`）。
- 沒有 migration、沒有新端點，契約不變。

## 11. 驗證

- 後端 pytest（真 PostgreSQL）：解析（手打 @、全形、同義字、校區前綴、短字只在有 @ 時）、各指令的內容與空狀態、校區群組只看自己校區、
  總部專用指令在校區群組被擋、待追蹤的按鈕能寫入園方自建的訪視、回覆不含電話與孩子姓名、限流。
- 沒辦法自動驗：真群組裡各卡片與長文字在手機上的樣子。
