## 1. 背景與目標

「新屋交屋」（B2）看的是**已經交屋**的房子；預售建案看**還在蓋、兩三年後才交屋**的房子，讓分校提早知道哪些里會有一批新住戶。

### 1.1 成功標準

1. 區域分析「里的變化」表多一欄「在建預售（戶）」，總結多一句；CSV 同步多欄。
2. 地圖多第六種著色「在建預售」（依里的戶數），有座標的建案另畫小點，彈出框寫案名、戶數、預計交屋（粗估）。
3. 區域分析多一張「附近預售建案」清單（半徑內、在建），依預計交屋排序，可匯出 CSV。
4. 正式站每月自動抓內政部檔；地號座標由本機腳本查、隨既有打包流程上傳，正式站不打國土測繪中心。
5. 不存起造人（含負責人姓名、自然人）。

## 3. 實作裁定

| # | 事項 | 裁定 |
|---|---|---|
| P1 | 主鍵 | (區, 建案名稱)；同鍵再出現視為同案更新。案名含 `?` 或私人區字元照存（來源缺字），顯示時不修 |
| P2 | 存哪些 | 區、案名、坐落街道原文、戶數、主要用途、是否住宅（主要用途含「住」）、申報備查日、建照日、第1次登記日、坐落基地第一筆地號（段名＋地號文字）、比對結果（里代碼、里名、比對等級、經緯度）、最後在檔中出現的版本日。**不存**：起造人、使用分區、建材、銷售期間、建造執照字號、編號 |
| P3 | 狀態（預設） | 住宅且**沒有**第1次登記日、建照日在今天往回 6 年內 →「在建」；有第1次登記日 →「已登記」；住宅、沒登記、建照超過 6 年或建照日空 →「不明」（不進在建統計，清單也不列）；非住宅不進任何統計 |
| P4 | 預計交屋（預設，粗估） | 建照日＋依戶數的月數：≤20 戶 25、21–100 戶 36、101–300 戶 48、>300 戶 52 個月；畫面只寫到半年（「約 2027 下半年」），一律標「粗估」。已過預計交屋還沒登記的，寫「已過預計時間（尚未登記）」，仍算在建。依據：2019–2022 建照、已登記者的中位數（實測 275 案） |
| P5 | 定位順序 | ①坐落基地第一筆地號在「地號座標表」有座標 → 用里界多邊形（`boundaries.village_code`）點入里，等級 `parcel`；②否則坐落街道比對門牌（`matcher.locate_parsed`，前面補「高雄市＋區」；有「與／及／和／、」時拆成多條路，各自比對，**所有路都到里而且是同一個里**才算該里，否則取第一條路的結果）；exact／nearby／street 算到里；③只到區。坐落街道本身是「段＋地號」格式的直接跳到 ③（除非 ① 命中） |
| P6 | 地號座標怎麼來 | 新指令碼 `backend/scripts/fetch_presale_parcels.py`（本機跑）：讀最新的建案檔（下載或本機路徑），把坐落基地第一筆地號解成（所碼, 段碼, 地號 8 碼）——段名用該區 NLSC 段清單**最長前綴**比對；讀既有輸出檔，只查還沒有的地號；每次請求間隔 ≥1 秒、User-Agent `ivy-website/1.0 (+presale-parcels)`，不帶任何帳號；輸出 `presale_parcels.csv`（`district,section_name,landno,office,sect,lon,lat,fetched_on`；查無寫空座標，下次不重查，除非 `--retry-missing`）。這個檔納入既有打包 `fetch_geo_bundle.py` 的 KINDS（`presale_parcels`），用 `geo-sync --bundle` 上傳匯入；CLI 另給 `--presale-parcels-file`。正式站同步迴圈**不打**國土測繪中心 |
| P7 | 地號座標表 | `geo_parcel_points`：(district, section_name, landno) 唯一，存 lon／lat（可空＝查無）、fetched_on。匯入是 upsert，不刪舊列（地號不會因為建案下架就失效） |
| P8 | 同步 | 新 dataset `presale_buildcases`（`DATASETS`＋DB check constraint migration，比照 `e4f1a8c6b203`）。`WEBSITE_GEO_AUTO_SYNC` 開著時每 30 天抓一次（`_series_due` 同規則）；`ETag` 沒變就只記 checked。整檔換版：新檔解析出的高雄筆數少於表內 80%（表內 ≥100）→ 不換、寫 `last_error`。單檔上限 2 MB（正常 180 KB）。換版時以新檔為準（不在新檔裡的案刪掉——來源是累計檔，消失代表撤案或更正） |
| P9 | 重比 | 地號座標匯入後、門牌換版後，都重比所有建案（661 筆，很快）；沿用 `new_homes.rematch` 的觸發點 |
| P10 | 里的變化欄位 | `presale_households`：該里「在建」住宅建案戶數合計（合併組同 B2：列上整組相加，另回 `presale_by_code` 給地圖）；沒匯入是 null、匯入了沒有是 0。總結一句：「半徑內在建預售 N 案、M 戶，最多的是 …（前 3 個里）」；沒對到里的案數寫小字 |
| P11 | 地圖 | 第六種著色「在建預售」，分級同 `levelOf`／`legendRanges`，單位「戶」；有經緯度（`parcel`、`exact`、`nearby`）的在建案畫小點（半徑內），彈出框：案名、戶數、預計交屋（粗估）、建照日、定位方式（「依地號」「依門牌」） |
| P12 | 附近預售建案清單 | 新元件，放在「里的變化」之後、「依國小學區」之前：半徑內（有座標用座標距離；只到里用里重心；只到區不列、計入小字）的在建案，欄位：案名、區／里、戶數、建照日、預計交屋（粗估）、距離。預設依預計交屋由近到遠。CSV 匯出同欄位。手機版收成卡片列表（沿用 `NearbyKindergartens` 的寬窄切換慣例） |
| P13 | 說明文字 | 「預售建案是內政部預售屋備查資料（110 年 7 月起）；戶數含店面以外的住宅單位、不等於已售出或已入住；預計交屋依建照日與規模粗估，誤差約半年到一年。」來源小字：「內政部實價登錄 預售屋建案備查；地號位置：國土測繪中心」 |

## 4. 不做

- 預測新住戶裡會有幾個幼兒、替里打分、合成指數（招生統計「不做」清單不變）。
- 起造人、建商排行、價格（預售成交 b 檔另案、10-14 §1.3 已排除）。
- 公開官網顯示。
- 正式站直接查地號。
- 歷史月份快照與「新增建案」趨勢（來源無快照；之後若要做，每月自己留版本，另案）。

## 5. API 與資料模型

- `geo_presale_buildcases`（P2 欄位＋`match_level`、`village_code`、`lon`、`lat`、`source_version`、`updated_at`），唯一鍵 (district, name)。
- `geo_parcel_points`（P7）。
- 里的變化端點（`trends.py`）：`villages[]` 多 `presale_households`、`presale_by_code`；`baseline` 多 `presale_households`、`presale_cases`；`sources.presale` 為 `{version, unplaced, note}`。
- 新端點 `GET /admin/admissions/area/presale?campus=&radius=`：回附近在建清單（P12）與地圖點（P11）；權限同區域分析其他端點。
- 契約：`npm run contract:generate` 後用不經 `uv run` 的等價檢查（見 memory：`export_openapi.py --check`＋`scripts/check-contract-types.mjs`）。

## 6. 測試

- 解析：壞行樣本（拆行、多逗號、空編號、日期錯）各一個固定測試檔（**起造人欄換成假公司名**，不放真實負責人姓名）。
- 定位順序 P5 每條路徑、多路名同里／不同里、段地號格式坐落街道。
- 狀態與預計交屋 P3／P4 邊界（6 年、各戶數級距）。
- 換版門檻 P8、ETag 未變、上限。
- 地號腳本：段名最長前綴、地號 8 碼轉換（`120-1`→`01200001`），網路用假回應，不打真站。
- 里的變化、合併組 `presale_by_code`、清單排序與距離、CSV 欄位。
- 前端：欄位、總結句、地圖著色與點、清單窄螢幕卡片。
