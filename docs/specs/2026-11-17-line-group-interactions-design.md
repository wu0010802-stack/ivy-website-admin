## 1. 為什麼做

群組目前只收單向的卡片通知（`notifications/line_flex.staff_card`）：新預約、已確認、已取消、已改期、24 小時內即將參觀。園務人員看到後還要開後台才能查名單、標記到場。目標是讓群組變成「看得到今天誰要來、問得到名額、按一下就標記到場」的工作介面，同時不增加每月推播則數（見 §6）。

## 3. 已查證的事實（影響設計）

來源：developers.line.biz 文件、本 repo `origin/main`（ffe857e3）。

- 群組裡主動推播「有幾個人收到算幾則」；**回覆（reply，用 webhook 的 replyToken）不計則數**。一次 push 裡有幾個訊息物件就算幾則。
- 群組 webhook 的 `source.userId` 文件寫「Only included in message events」，**postback 事件不保證有**。
- Flex 訊息不能放 @提及；只有 `textV2` 文字訊息能用 `substitution` 做 @user／@all（只限 reply／push 到群組或多人聊天室）。
- 同一時間一個群組只能有一個官方帳號；群組不支援 multicast；圖文選單只在一對一聊天顯示（本專案不依賴）。
- 現有 `line_campus_targets` 以 `campus_key` 為主鍵（一校一個群組），**同一個群組可以收多校**；`line_groups.verified_at` 是「有人貼過後台產生的驗證碼」，只有驗證過的群組能被選為推播目標。
- 現有狀態機：`mark_completed`／`mark_no_show` 只能從 `confirmed` 轉，**之後改不回來**；`mark_completed` 在同一交易會寫廣告轉換回傳（`visit_attended`，worker 立刻送 GA4／Meta／OpenAI／LINE）、建立招生訪視（`admissions_enabled` 開時）、寫分析事件。`mark_no_show` 只能在場次開始後。提早到（`complete-early`，10-12 裁定）可標記完成並釋出之後日期的名額。
- webhook 驗簽、`_target`、`LineGroup` 紀錄都在 `notifications/line_routes.py`，不存任何訊息內容；`PARENT_MESSAGE_LIMIT` 已有限流元件可沿用。

## 4. 各項設計

### 4.1 每日摘要（項目 1）

- `workers/maintenance.py` 每輪（60 秒）檢查：台灣時間 08:00–12:00、這個群組今天還沒發過摘要 → 直接推播，成功後寫一筆 `line_digest_runs(target_id, digest_date)` 去重；失敗下一輪重試到 12:00。（**不經 outbox**：`outbox_messages.visit_request_id` 是 NOT NULL 外鍵，摘要不屬於任何案件。11-17 查程式後修正。）
  - **2026-11-17 施工修正**：實作在 `notifications/line_digest.py`，去重表就是 `line_digest_runs`；發送窗 `DIGEST_START`～`DIGEST_END` ＝ 台灣時間 08:00–12:00（12:00 整點起不再發）。目標清單用 `line_group_settings.digest_targets`，名單查詢用 `rows_between`，§4.2 的群組查名單與 §5 的按鈕沿用同一組函式，不另寫一套。
- 內容：一個 Flex carousel。第一張是總覽（日期、各校當天筆數）；之後每筆已確認的參觀一張（時段、校區、家長稱呼 ≤20 字且拿掉網址，和 `staff_card` 同一套清理；**不放電話、Email、孩子資料**），帶 §5 的按鈕。LINE carousel 上限 12 張，超過 11 筆時最後一張寫「另有 N 筆，請開後台」。
- 當天沒有任何已確認參觀就不發。
- 以「群組」為單位：一個群組服務多校（總部群組）時一則摘要，按校區分段。
- **取代**：群組的 `visit_upcoming`（即將參觀）卡片不再推（站內通知與寄信照舊）。群組關掉摘要開關時，該群組退回原本逐筆推 `visit_upcoming`，不會變成什麼都沒有。
- 摘要只推 LINE，不寫站內通知、不寄信，也沒有新的通知種類（不需補 `_KIND_LABELS`）。

### 4.2 群組查名單（項目 2）

- 觸發字（整則訊息完全相符，前後空白可忽略；**我的決定**：不用單字「今天」以免日常閒聊誤觸）：`今天參觀`、`明天參觀`、`本週參觀`（本週＝今天起到本週日）。@官方帳號時也接受不帶「參觀」的短字（見 4.7）。
- 回覆（reply，不計則數）：同 4.1 的 carousel，但依時間排序、含按鈕；沒有就回一句「這段時間沒有參觀預約」。
- 可查的校區：這個群組是「校區群組」就是它服務的那幾校；是「總部群組」就是五校。群組若不是任何校的目標、或 `left_at` 不為空，不回應。
- 限流：每群組每分鐘最多 6 次查詢（沿用 `ratelimit`）。
- **2026-11-17 施工修正（實作與上列一致，補細節）**：指令只認整則訊息完全等於「今天參觀」「明天參觀」「本週參觀」；「今天」「明天」「本週」短字只有在訊息 @ 了官方帳號時才認；@ 那一段依 `message.mention.mentionees` 裡 `isSelf` 的 `index`／`length`（UTF-16 code unit）切掉，可在句首或句尾、名稱含空白或 emoji 都行，別人的 @ 不切；`index`／`length` 不能用時退回「剝掉開頭 @… 到第一個空白」。多人聊天室（roomId）與群組同樣處理。第 7 次查詢（同群組同一分鐘）直接忽略、不回覆。§4.6 的使用說明（`memberJoined`、`join`）同群組 10 分鐘只回一次。

### 4.3 卡片顏色（項目 7）

`line_flex._bubble` 的標題色改成依 kind：新預約深綠（現行 `BRAND`）、已確認藍、已改期橘、已取消紅；文字色與按鈕色同步調整，對比度要在白底量過（標題文字 ≥ 4.5:1）。

**2026-11-17 施工修正**：已改期標題色不用原先預想的 `#C4631A`（白底只有 4.08:1，不到本節要求的 4.5:1），改用 `#B35A14`（4.78:1）；新預約 `#244933`、已確認 `#1F5FA8`、已取消 `#B3261E` 照原案。postback 按鈕用 Flex `style: "link"` 搭種類色；LINE 的 `color` 在 `secondary` 按鈕上是「背景色」，字色會被蓋掉，所以不用 `secondary`。顏色常數集中在 `line_flex.py`（這支檔案本來就是 hex，LINE 不吃 CSS 變數；網站與後台的色碼規則不適用）。取消卡片不放到場按鈕。

### 4.4 每群組開關與總部群組（項目 8）

- 新表 `line_group_settings`（`target_id` PK、FK `line_groups`）：`kinds` JSONB（開啟的通知種類，預設＝全部：新預約、已確認、已取消、已改期）、`digest_enabled`（預設 true）、`mention_all_same_day`（預設 true）、`is_hq`（預設 false）。沒有設定列＝全部預設值，既有群組行為只有「摘要取代即將參觀卡片」這一項改變。
- 總部群組：`is_hq=true` 的群組**額外**收所有校區的通知（和校區群組並存，不取代；`line_campus_targets` 的一校一群組限制不動）。推播時目標＝校區群組 ∪ 所有 `is_hq` 群組，各自套用自己的 `kinds`。
  - **2026-11-17 施工修正**：`kinds` 只管四個員工種類（新預約、已確認、已取消、已改期）；`visit_upcoming` 與其他非員工種類**不受 `kinds` 過濾**，`visit_upcoming` 只看該群組的 `digest_enabled`（開著時由每日摘要取代，關著時退回逐筆推）。總部群組是在校區群組之外額外收，不取代。`notification_deliveries` 的 `channel=line`、`recipient_key=target_id` 已能分辨多個目標。
- 後台：`LineNotificationsView.vue` 每個群組多一列開關（四個種類、摘要、@所有人）與「設為總部群組」。權限沿用現有 LINE 通知設定的 capability；稽核動作 `line.group.settings.update`（要在 `auditLabels.ts` 歸類）。
- 契約：新增或改的 API 要跑 `npm run contract:generate`／`contract:check`。

### 4.5 @所有人（項目 11）

- 條件：種類是新預約、已改期、已取消，且**相關場次日期是今天（台灣時間）**（改期看新場次，取消看被取消的場次），群組 `mention_all_same_day` 開著。
- 作法：同一次 push 多帶一個 `textV2` 訊息（`{everyone} 今天有臨時變動，請看上方卡片`，substitution 用 `mentionee: {type: "all"}`）。**這會讓那一次推播多算一則**，只有當天異動才會發生，頻率低。
- altText 與卡片內容不因此多放個資。

### 4.6 新成員說明（項目 12）

- 收到 `memberJoined`（以及官方帳號自己被拉進群組的 `join`）事件：用 replyToken 回一則使用說明（可用指令、按鈕怎麼用）；不計則數。
- 同一群組 10 分鐘內只回一次（一次拉很多人進來不洗版）。
- 群組不是任何校的目標也不回（避免陌生群組把帳號拉進去就得到說明）。

### 4.7 @官方帳號（項目 13）

- `message.mention.mentionees` 有 `isSelf: true` 就視為叫出選單：回一張 Flex 卡片，三顆按鈕（今天參觀、明天參觀、本週參觀）。按鈕用 **message action**（按了會以按的人的名義在群組送出那串字，再由 4.2 處理）。
- **我的決定**：用 Flex 按鈕而不是 quick reply，因為 quick reply 在群組顯示行為我沒從文件確認；Flex 按鈕在群組一定能用。
- @官方帳號後如果同則訊息含「今天／明天／本週」也直接當查詢處理。

## 5. 已到場／未到場按鈕（項目 4，做法 A，含一項修正）

**使用者選的 A 含「復原」按鈕；查程式後無法照做，改成「二次確認」，這是我的決定，需要使用者確認。**

為什麼不能復原：標記已到場／未到場是單向的（只有 `confirmed` 能轉；後台也改不回來），而且已經在同一交易排了廣告轉換回傳（worker 立刻送出去，收不回來）、建立了招生訪視。要做復原得新增狀態轉換、撤回已送出的廣告事件與招生訪視，範圍遠超這個專案。

改為：

1. 卡片／名單每筆有兩顆按鈕：「已到場」「未到場」（postback，`data` 只放動作與案件 id，< 300 字元）。
2. 按下去**先不寫入**，回覆一張確認卡：「確認〈家長稱呼〉〈時段〉已到場？」＋「確認」「取消」。按「確認」才寫入。這樣誤按至少有一次機會攔住，群組裡也留得下是誰按的（displayText）。
3. 寫入走現有 `workflow_service.mark_completed`／`mark_no_show`（同一個函式，同交易的招生訪視、廣告回傳、分析事件照舊），傳入 `Settings.admissions_enabled`；**不另寫一套狀態邏輯**。完成後回一則結果（回覆，不計則數）：「已標記〈家長稱呼〉已到場」。
4. 授權：事件的 `source.groupId` 必須是**該案件校區目前的推播目標**（校區群組或 `is_hq` 群組）、`LineGroup.left_at` 為空；否則回「這個群組沒有權限處理這筆」。
   - **2026-11-17 施工修正**：沒綁任何校區（或已離開）的群組按按鈕，**完全不回應**（回「沒有權限」等於讓陌生群組能探測案件是否存在）；只有「已綁校區、但案件屬於別校」的群組才收到「這個群組沒有權限處理這筆」。群組內任何成員都能按（群組本身已經過後台驗證碼證明有後台人員在內）。
   - **2026-11-17 最終審查修正**：上一點的前提改成程式檢查：按鈕（含確認、招生結果欄位、取消）只在 `line_groups.verified_at` 不為空的群組有作用；2026-09-29 以前綁定、沒驗證過的舊群組照常收卡片、摘要與查名單，但按鈕不回應（同沒綁校區）。多人聊天室（roomId）可以被選為目標，按鈕與群組同樣處理。總部群組被移出（`leave`）時 `is_hq` 改回 false，再被拉回來不會自動恢復總部身分。
5. 時間規則沿用後台：已到場在場次開始後可按，**場次是今天但還沒開始也可按**（提早到，用 `arrives_early`＋`early=True`）；場次是之後的日子 → 回「要到參觀當天才能標記」。未到場只能在場次開始後。案件已不是 `confirmed`（已被別人標記或取消）→ 回目前狀態，不再寫入。
6. 操作者記錄：`VisitEventSource` 新增 `LINE_GROUP`（值 `line_group`，歷程時間線顯示「LINE 群組」；**2026-11-17 施工修正**：`visit_request_events.source` 是 `String(16)`、沒有 CHECK，不需要 migration）；`actor_user_id` 為空。稽核 `line.group.visit_attend`／`line.group.visit_no_show`，metadata 記 `group_id`，事件帶得到 `userId` 就一併記（文件不保證）。
7. 防重放：確認的 postback 帶無狀態 token（HMAC，含動作、案件 id、到期 5 分鐘；不存任何東西；**2026-11-17 施工確認：實作就是無狀態 HMAC，沒有新表**），過期回「這個確認已過期，請重新按一次」。重放已成功的確認時案件已不是 `confirmed`，只會回目前狀態，不會重複寫入。
8. 預約已取消的卡片不放這兩顆按鈕。

### 5.1 到場後的招生資料（使用者 11-17 問「到場後要填的資料可以在 LINE 做嗎」，選「結果欄位按鈕＋後台連結」）

**原則**：只在 LINE 填「按鈕選得出來、不含個資」的結果欄位；姓名、生日、電話、地址、父母職業、介紹人、備註、家長回應這類個資或自由文字**一律不在群組輸入**（群組多人共看、聊天紀錄留存，也違反 10-05「群組不放電話與孩子資料」裁定）。

**已知事實**（`booking_link.fields_from_visit_request`）：標記已到場建立招生訪視時，孩子姓名、生日、年級、電話、聯絡人、來源（家長勾的「從哪裡知道我們」）、備註（家長想了解）、預計入學學期已自動帶入；**沒帶入**的是地址、父母職業、介紹人、預繳結果、來源分類、未預繳原因、搭交通車、家長回應、英文名。LINE 負責其中的按鈕型欄位，其餘留給後台。

**流程**（只有招生入學功能開著、且這筆預約有招生訪視時才出現；否則結果卡只放後台連結）：

1. §5 第 3 點的結果卡（「已標記〈家長稱呼〉已到場」）下方多三排按鈕：
   - 預繳結果：「已預繳」「未預繳」。按「已預繳」**先回確認卡（二次確認）**，按確認才走漏斗階段轉換（`funnel.py`，同後台「標記預繳」，寫 `deposit_added` 歷程），**不直接改 `has_deposit`**。按「未預繳」回一張原因卡，八個原因照 `constants.NO_DEPOSIT_REASONS` 的順序與字面；選了才寫 `no_deposit_reason`（`records.update_visit`）。
   - 來源分類：按下去回一張選擇卡，**六項**（**2026-11-17 施工修正**：使用者 10-06 裁定來源分類收斂為六項，後台表單也只顯示這六項；順序與短標籤同 `admin/src/admissions/sourceCategories.ts`，後端常數為 `constants.LINE_SOURCE_CHOICES`：sibling_current、sibling_graduate、referral、self_report、invite_success、returning；寫 `source_category` 代碼）。
   - 搭交通車：「搭」「不搭」（`rides_bus`）。
   - 最下面一顆「到後台填完整資料」：`admin_visit_url(..., external_browser=True)`（開案件頁 `/admin/visit-requests/<id>`，後台既有的到場後招生表單從那裡開；`openExternalBrowser=1` 避開 LINE 內建瀏覽器擋 Google 登入）。
2. 每一次按鈕只寫一個欄位，回覆（不計則數）「已記錄：〈欄位〉〈值〉」。寫入用當下讀到的 `version` 做樂觀鎖；版本衝突（剛好有人在後台改）就重讀一次再寫，仍衝突則回「資料剛被更新，請再按一次」。
3. 授權同 §5 第 4 點：`source.groupId` 必須是該招生訪視所屬校區目前的推播目標；`visit_request_id` 沒有對應招生訪視、或招生訪視已匿名化／已退出，回「這筆已不能在群組填寫」。**2026-11-17 施工修正**：招生入學功能關閉時，結果欄位按鈕一律回同一句「這筆已不能在群組填寫」，不寫入任何東西。
4. **2026-11-17 施工修正**：其餘欄位按鈕（未預繳原因、來源分類、搭交通車）不做二次確認（不是單向、不送廣告回傳），同一欄位可再按來更正；**「已預繳」要二次確認**——它會排一筆不可撤回的廣告轉換回傳，和已到場同性質，確認卡的「確認」帶無狀態 HMAC token（綁動作與招生訪視 id、5 分鐘到期）。預繳一旦按了「已預繳」，LINE 這邊不提供取消預繳（會走 `deposit_removed` 與退預繳的語意），再按「未預繳」回「已是預繳狀態，要更正請到後台」。
5. 操作者：招生歷程的 `actor_user_id` 為空。**2026-11-17 施工修正**：歷程 `metadata` **不帶** `source: line_group`（要帶得改 records／funnel 的簽章，不值得），追溯來源是稽核紀錄；稽核 `line.group.recruitment_field`，`metadata` 只記欄位名與值的代碼，不記自由文字。`auditLabels.ts` 要歸類。
6. postback `data` 只放動作代碼、招生訪視 id、值的代碼（原因與分類用索引或代碼，不放中文字面），遠低於 300 字元上限。結果卡上的欄位按鈕不設過期（「已預繳」確認卡的 token 例外，5 分鐘）（欄位低風險、可更正，且每次都重新驗群組授權）。

**不做**：在群組打字填任何欄位、LIFF 表單（要另外申請 LINE Login channel，工程量是這個專案的數倍）、備註與家長回應。

**前提與提醒**：招生入學正式站開關目前是開的，但招生用途的隱私權政策還沒補（規格 Q1，見 `deploy/README.md`）；這項功能沒有新增蒐集的個資種類，不會讓該缺口變大，但上線前仍建議先補。
