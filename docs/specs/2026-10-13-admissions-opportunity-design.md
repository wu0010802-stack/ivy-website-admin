## 1. 背景與目標

使用者要一個「令人驚艷、不是 AI」的功能，從四個方案裡選了招生機會地圖。它重開 10-08 區域分析規格 §3.2 延後的「市場資料：0–6 歲人口、飽和度、機會判讀（D1）」中的**人口與機會判讀**兩項；飽和度仍不做（見 1.3）。

區域分析目前只看得到「家長從哪裡來」。加上內政部各里的學齡前人口後，就能回答：

- 本校附近哪些里的孩子最多？
- 哪些里孩子很多、來參觀的卻明顯比附近少？發傳單、辦社區活動、掛布條該先去哪裡？
- 哪些里再過兩年會有一批孩子到幼兒園的年紀？

### 1.1 成功標準

1. 招生入學 → 統計分析 → 區域分析，地圖可以切換「參觀人數／2–5 歲孩子／招生機會」三種著色。
2. 地圖下方新增「招生機會」：一句總結（本校 N 公里內幾個里、多少孩子、參觀率、明顯偏少的里合計少了約幾位），加一張可匯出 CSV 的里排行。
3. 半徑跟著現有的 1／3／6 公里選擇走（附近幼兒園那一個），換半徑地圖與排行一起換。
4. 各里人口每月自動更新（`WEBSITE_GEO_AUTO_SYNC` 開著時），正式站連不到來源時有 CLI 檔案匯入的退路，和門牌一樣。
5. 家長資料不送任何外部服務；新端點只回聚合數字與公開人口資料。

### 1.2 實作裁定（2026-10-13，預設值，業主可改）

| # | 事項 | 裁定 | 理由 |
|---|---|---|---|
| O1 | 「孩子」算哪些年紀 | **2–5 歲**（統計月底的足歲），另列 **0–1 歲** | 幼幼班 2 歲入園，6 歲多半已上小一（分班規則 `web/app/utils/admission-classes.ts`）；0–1 歲是兩年內會到幼兒園年紀的孩子 |
| O2 | 哪些里算「附近」 | 里界的**面積重心**在本校半徑內 | 簡單、說得清楚；半徑沿用 1／3／6 公里 |
| O3 | 參觀率 | 範圍內到里的參觀人數 ÷ 該里 2–5 歲孩子數，百分比小數一位 | 母體同其他子分頁（頁首校區＋入學學年學期） |
| O4 | 拿什麼比 | **附近平均**＝半徑內參觀合計 ÷ 2–5 歲孩子合計；每個里「照附近應有」＝孩子數 × 附近平均 | 只和自己附近比，不和全市比（五校商圈不同） |
| O5 | 判讀門檻 | Poisson：實際 ≤ 應有，且 P(X ≤ 實際 \| 應有) ≤ 0.10 →「明顯偏少」；P(X ≥ 實際 \| 應有) ≤ 0.10 →「比附近多」；其餘「差不多」 | 和「本月預繳比過去慢」「來源結構失衡」同一個 p ≤ 0.10：完全正常的里約一成會被標 |
| O6 | 什麼時候不判斷 | 半徑內參觀合計不到 **10 位**：整張表不判斷；某里應有不到 **1 位**：寫「孩子少，看不出來」 | 同預繳速度「比較組少於 10 筆不判斷」；應有不到 1 位時，0 位也不算少 |
| O7 | 排序 | 「應有－實際」由大到小；同值依孩子數、再依名稱 | 少最多的里排最前面；不另算分數 |
| O8 | 「可能範圍」 | **不放** | 參觀率多半在 1% 上下，現有可能範圍四捨五入到整數會變成「0–1%」，沒有資訊；改放「照附近應有約 N 位」 |
| O9 | 地圖預設模式 | 參觀人數（現狀） | 不改現有畫面與視覺基準；新模式由使用者自己切 |

### 1.3 不做

- **飽和度**（附近園所核定人數 ÷ 孩子數）：園所核定人數不等於實際收托，公私立與準公共的家長族群也不同，算出來的比例容易誤導。要做另開。
- **預測、個別家長的意願評分**：已否決（DESIGN.md 招生統計「不做」、`docs/analysis/2026-09-30-enrollment-analytics-report.md` §1）。這裡只拿實際參觀和公開人口做描述性比較，不推估未來、不對任何一戶打分。
- **「小小孩比例偏高」旗標**（0–1 歲占 0–5 歲的比例高於全市）：用 115 年 9 月資料試算，單尾二項檢定 p ≤ 0.10 時全市 893 里標出 103 個（11.5%），和完全隨機時的一成誤報差不多，多半是雜訊；只列 0–1 歲人數，不下結論。
- **各校 3／6 km 競爭環、Google 評分、車程**：10-08 已否決，理由不變。
- **公開官網顯示人口地圖**：只在後台。
- **人口資料的歷史月份比較**：只存使用中的一個月份。

## 4. 同步

併進既有的公開資料同步（`app/admissions/geo/sync.py` 的 `run_geo_sync`），成為第三種資料，各自成敗：

- **背景**：同門牌、幼兒園，`WEBSITE_ADMISSIONS_ENABLED` 與 `WEBSITE_GEO_AUTO_SYNC` 都開才跑；資料表空時立刻抓，之後距上次確認超過 30 天才去看來源。
- **找最新月份**：從今天（台北）的上一個月往回最多試 4 個月，第一個 `responseCode` 是 `OD-0101-S` 的就是最新。和使用中的月份一樣且沒有 `--force`：只更新 `checked_at`。比使用中的舊：不換（同門牌）。
- **下載**：一律帶 `COUNTY=高雄市`。第 1 頁拿到 `totalPage` 後依序抓完（上限 10 頁，超過視為來源異常）。解析時（`json.loads` 的 `object_hook`）就只留 `district_code` 以 `64000` 開頭的列與 0–6 歲欄位：來源哪天不理會 `COUNTY` 也不會把外縣市寫進來，記憶體也不會隨全國資料膨脹。實測真實 115-09 高雄一頁：解析峰值約 22 MB、0.4 秒；若退回全國四頁約 90 MB。
- **驗證**（任一不過就不換、保留使用中的版本，寫 `last_error`）：
  - 每列的 `statistic_yyymm` 都等於這次的月份；
  - 數字欄是非負整數；
  - 代碼在里界檔裡（對不到的列略過、計數）；
  - 對到的里至少 **850** 個（高雄 893 里；殘缺檔不換）；
  - 同一個代碼不重複。
- **CLI 退路**：`python -m app.cli geo-sync --population-file <JSON> [--population-file <JSON> …]`：給 API 的原始回應檔（帶 `COUNTY=高雄市` 是一個檔；全國的四頁也收，解析時只留高雄），月份取資料本身的 `statistic_yyymm`。指定任一個檔案就完全不連外（和門牌、幼兒園同一個規則）；檔案匯入一樣要過驗證。
- `last_error` 只記我們自己的訊息或例外類別，不含回應內容。

## 5. 計算（`app/admissions/opportunity.py`，只讀）

1. 範圍內的訪視：母體 `_base_filters(campus_key, school_year, semester)`，比對到里（`exact`／`nearby`／`street`）且未匿名化的，依（區, 里）分組計參觀人數；(區, 里) 以里界檔轉代碼。
2. 本校座標：沿用 `matcher.campus_point`。沒有座標：不算，回 `campus.locate_error`。
3. 里的重心：里界檔每個里的面積加權重心（多邊形外環的 shoelace 重心，MultiPolygon 依面積加權），程式啟動後第一次用到時算一次並快取。
4. 附近的里：重心到本校的直線距離 ≤ 半徑。距離取整到 100 m。
5. 附近平均 `r`＝附近各里參觀合計 ÷ 2–5 歲孩子合計；孩子合計為 0 時沒有平均。
6. 每個附近的里：`expected = children × r`；`shortfall = expected − visit`；判讀依 1.2 的 O5、O6。
7. 另外算兩個數字，畫面寫在總結下面：範圍內**到里但在半徑外**的參觀人數（`outside_visit`）、**沒對到里**的參觀人數（只到區、未定位、待比對、沒填地址、已匿名化；`unplaced_visit`）。它們不算進附近平均。

Poisson 累積機率用標準函式庫自己算（`estimation.poisson_cdf`／`poisson_sf`，對數空間逐項加總），不新增套件，和 `estimation.py` 其他函式一樣將來可以整支搬進園務。

## 6. API

`GET /api/website/v1/admin/admissions/area/opportunity`，招生開關底下；權限 `_require_campus(user, "admissions.read", campus_key)`；只讀、不寫稽核。

參數：`campus_key`（必填）、`school_year`、`semester`（同 `/area`）、`radius_km`（1／3／6，預設 3；其他值與非整數回 422 `INVALID_RADIUS`，同 `/area/kindergartens`）。

回應 `AreaOpportunityOut`：

| 欄位 | 說明 |
|---|---|
| `as_of`、`filters`、`radius_km` | 同 `/area` |
| `population` | `version`（「115-09」，未匯入為 null）、`synced_at`、`age_band`（固定 `"2-5"`）、`source_note`（「資料來源：內政部戶政司…」） |
| `campus` | 同 `/area` 的 `AreaCampusOut` |
| `baseline` | 沒有人口資料或本校沒座標時為 null；否則 `villages`、`children`、`infants`、`visit`、`rate`（百分比，分母 0 為 null）、`judged`（參觀合計 ≥ 10） |
| `outside_visit`、`unplaced_visit` | 見 5.7 |
| `villages[]` | `district`、`village`、`village_code`、`distance_m`、`children`（2–5 歲）、`infants`（0–1 歲）、`visit`、`rate`、`expected`（小數一位，沒有平均時 null）、`shortfall`（小數一位）、`signal`：`below`／`typical`／`above`／`few_children`／`not_judged`；依 O7 排序 |

`/admin/admissions/area` 的 `data_status` 另加 `population_version`、`population_synced_at`（給狀態列）。

## 7. 後台畫面

### 7.1 狀態列

「門牌資料 115 年 10 月版・幼兒園名單 10/12 更新・各里人口 115 年 9 月」；人口沒匯入時最後一段寫「各里人口尚未匯入」。

### 7.2 地圖

- 圖例上方加三段切換：**參觀人數**（預設，現狀）／**2–5 歲孩子**／**招生機會**。人口沒匯入、本校沒座標、讀取失敗時，後兩個停用並在旁邊寫原因，正在看的人退回參觀人數。讀取中（例如換半徑）不停用、不跳回，地圖先不上色、彈出框寫「招生機會讀取中…」。
- 2–5 歲孩子：半徑內的里依孩子數分 5 級（同參觀人數的 5 級切法與顏色），半徑外不上色。
- 招生機會：明顯偏少用 `--area-chance`（新 token，玫瑰色，避開狀態綠、草稿暖黃、四種幼兒園類型色）、比附近多用 `--area-level-4`、差不多用 `--area-level-1`、孩子少與不判斷不上色；半徑外不上色。
- 點里的彈出框（後兩種模式）：「三民區鼎金里」／「2–5 歲 412 位・0–1 歲 150 位」／「參觀 3 位（0.7%），照附近應有約 6 位」／判讀（「明顯偏少，少了約 3 位」等）；有參觀才有「查看明細」。半徑外的里寫「不在本校 3 公里內」。
- 地圖容器的 aria-label 跟著模式換（「…依招生機會著色」）。

### 7.3 招生機會區塊（地圖與附近幼兒園之下、三張表之上）

- 標題「招生機會」，副標「本校 3 公里內」（跟半徑走）。
- 總結：「本校 3 公里內 130 個里，2–5 歲孩子 12,883 位，參觀 96 位（參觀率 0.7%）。明顯偏少的里 5 個，照附近的參觀率合計少了約 31 位。」沒有明顯偏少的里時後半句改「沒有明顯偏少的里。」；不判斷時改「附近參觀還不到 10 位，先不判斷哪些里偏少。」
- 小字：「另有 N 位來自 3 公里外、M 位沒對到里，不算在內。」（兩者為 0 的部分不寫）
- 表格（`StatsDimensionTable`，可匯出 CSV）：里（固定欄）、距本校、2–5 歲（長條）、0–1 歲、參觀人數、參觀率、照附近應有、判讀。判讀文字：「少了約 N 位」（明顯偏少）／「比附近多」／「差不多」／「孩子少，看不出來」／「還不判斷」。CSV 的「照附近應有」寫數字（小數一位），不寫「約」。
- 表格說明（caption）：「2–5 歲、0–1 歲取自內政部戶政司 115 年 9 月各里人口；參觀率＝參觀人數 ÷ 2–5 歲孩子數；照附近應有＝孩子數 × 本校附近的參觀率。明顯偏少的判斷約有一成機率是誤報。」
- 空狀態：人口未匯入「各里人口資料尚未匯入；匯入後就能看哪些里孩子多、參觀少。」；本校沒座標「本校位置未標示（原因），算不出附近有哪些里。」；讀取失敗顯示錯誤與重試，不影響地圖與其他表。

### 7.4 手機

區塊與表格沿用 `StatsDimensionTable` 的手機規則（框內橫捲、名稱欄固定）；切換鈕可換行，不撐出頁面。
