# 三輪 QA 修正交接（2026-11-18）

三輪 QA 的重現基於 `feature/website-admin` 的 `d11d7e79`。本次修正分支從 `main` 的 `14900354` 出發，逐項核對 20 個發現。這次補強三處，其他 17 項已有防護或隨流程改版移除。

| QA 發現 | 指定分支的處理 |
| --- | --- |
| 後台切換案件後顯示與寫入對象不一致 | `useVisitCase` 忽略前一筆晚回的資料，寫入綁定操作開始時的案件 |
| 同時停權後沒有總管理者 | 後端用交易層級 advisory lock 序列化停權並重新計數 |
| 同一預約重送最後名額時誤報額滿 | 取得預約設定列鎖後再次檢查冪等重播 |
| 「不用再追」未清除原日期 | 明確的 `clear_follow_up` 清除已存日期 |
| 撤銷家長連結時仍產生有效 session | 連結交換在 token 列鎖內驗證，與撤銷互斥 |
| 可同時建立兩筆待核准改期 | 舊申請端點回 410，現行家長改期直接在案件與場次鎖下執行 |
| 發布中切校造成狀態污染 | 編輯器操作時鎖定校區切換，回應套用前也比對校區 |
| 素材 A 儲存的慢回應關閉素材 B 編輯 | 素材儲存時停用取消，關閉視窗的共用守衛也會攔下 |
| 站內通知缺查看案件 | 用 `receipt_id` 建立案件連結，保留舊欄位相容 |
| 改期核准頁不顯示新日期時間 | 人工核准列表與端點已移除 |
| 分校管理者預設上傳回 403 | 預設自己的可用校區，分校帳號須選校區 |
| 素材說明或來源標註過長回 500 | UI 與 API 都有 500／255 字上限，API 回 422 |
| 歷史版本重發引用已刪素材 | 有歷史引用的素材禁止刪除，發布前也重驗素材仍可用 |
| 兩人同時首次開啟 CMS 編輯器時其中一人回 500 | **本次修正**。共用與分校內容都透過唯一索引建立或讀回同一項目 |
| 家長 A 分頁可能取消 B 的預約 | **本次補強**。現行頁面已帶案件 ID，現在也拒絕未帶 ID 的舊頁面取消請求，回 409 提示重開連結 |
| SQL 還原遇到錯誤仍回成功 | 還原已使用 `ON_ERROR_STOP=1` 與單一交易 |
| 通知租約接手後可重複發送或覆寫工作狀態 | **本次修正**。送通知的連線跨提交持有 PostgreSQL advisory lock。確認完成、失敗及略過前驗證原租約，過期 worker 無法覆寫已接手的工作 |
| 匿名化後聯絡紀錄仍含個資 | 匿名化保留聯絡紀錄的時間與次數，遮蔽內容 |
| 分校總覽混入他校失敗通知數 | 失敗通知統計已依校區過濾 |
| 超過 72 bytes 的密碼尾碼遭截斷 | 新建與重設密碼已拒絕超長輸入，既有帳號的登入相容策略沿用基底設計 |

QA 的測試隔離問題也已改善。`backend/tests/conftest.py` 會採用 `WEBSITE_TEST_DATABASE_URL`，本次使用額外建立的本機 PostgreSQL 庫。部署 workflow 以 `main` 為正式部署分支。

新增迴歸測試涵蓋共用與校區 CMS 首次併發、通知工作跨提交互斥與三種過期租約更新、缺少案件 ID 時保留預約。七個測試在原基底失敗，修正後通過。通知測試模擬發送，未連外部服務。連線斷開或供應商已接受通知但服務未能寫入交付紀錄時，仍依原有重試與供應商冪等策略處理。

本機兩批後端測試分別通過 64 與 101 項，兩批涵蓋部分相同案例。官網單元測試通過 2,480 項（含工作目錄原有的兩個代理測試），後台相關單元測試通過 194 項。官網及後台型別檢查、API 契約與狀態機檢查均通過。完整 CI 由功能分支推送觸發。
